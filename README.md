# Telegram-бот для коллективной генерации кода

Это реализация тестового задания для Python Backend разработчика. Бот позволяет группе пользователей коллективно, строка за строкой, писать код путем голосования за предложенные варианты.

## Основной функционал

*   **Генерация кода через опросы:** Бот использует LLM для генерации 4 вариантов следующей строки кода на основе уже написанного текста.
*   **Коллективное принятие решений:** Участники чата голосуют за наиболее подходящий вариант.
*   **Сборка кода:** Строка, набравшая больше всего голосов, добавляется в общую историю кода.
*   **Персистентность:** Вся история кода и состояние активных опросов сохраняются в базе данных SQLite.
*   **Администрирование:** Специальные команды для управления процессом доступны только администраторам.

## Технический стек и архитектура

Проект построен на принципах чистой архитектуры с разделением на слои (Handlers, Services, Database) для обеспечения высокой тестируемости и слабой связанности модулей.

*   **Фреймворк:** `aiogram 3.2`
*   **База данных:** `SQLite` + `SQLAlchemy 2.0` (асинхронный режим)
*   **Управление зависимостями:** `Poetry`
*   **Тестирование:** `pytest` с `pytest-asyncio` и `pytest-cov` для юнит-тестирования.
*   **Контейнеризация:** `Docker` и `Docker Compose`.
*   **Качество кода:** `ruff` для линтинга и форматирования.
*   **LLM API:** Архитектура позволяет подключать любой OpenAI-совместимый API.

### Примечание о LLM API

В ходе разработки была реализована гибкая архитектура, позволяющая подключать любой OpenAI-совместимый API (Groq, Deepseek, OpenAI и др.).

Однако при попытке подключения к внешним API возникли непреодолимые проблемы на уровне сети, связанные с геоблокировкой запросов из РФ.

Для демонстрации полной работоспособности приложения (логика опросов, работа с БД, асинхронная архитектура, обработка команд) в качестве LLM-провайдера был реализован и по умолчанию подключен **`MockLLMClient`**. Он полностью имитирует ответы нейросети, позволяя проверить весь функционал бота.

**Для переключения на реальный API** необходимо:
1.  Указать валидные `LLM_API_KEY` и `LLM_API_BASE` в файле `.env`.
2.  В файле `src/code_gen_bot/__main__.py` заменить `MockLLMClient` на `OpenAIClient`.

Код для `OpenAIClient` полностью готов к работе.

## Установка и запуск

### Вариант 1: Запуск через Docker (рекомендуемый)

Этот способ является предпочтительным, так как он не требует установки Python или зависимостей на хост-машину.

**Требования:**
*   Docker
*   Docker Compose

**Инструкция:**

1.  **Клонируйте репозиторий.**
2.  **Создайте файл `.env`** на основе `.env.example` и впишите свои данные (`BOT_TOKEN`, `ADMIN_IDS`).
3.  **Запустите бота:**
    ```bash
    docker-compose up --build -d
    ```
4.  **Просмотр логов:**
    ```bash
    docker-compose logs -f
    ```
5.  **Остановка:**
    ```bash
    docker-compose down
    ```

### Вариант 2: Локальный запуск через Poetry

**Требования:**
*   Python 3.10+
*   Poetry

**Инструкция:**

1.  **Клонируйте репозиторий.**
2.  **Создайте файл `.env`** на основе `.env.example`.
3.  **Установите зависимости:**
    ```bash
    poetry install
    ```
4.  **Запустите бота:**
    ```bash
    poetry run python -m code_gen_bot
    ```

Проект покрыт юнит-тестами для слоя работы с базой данных. Для запуска тестов и просмотра отчета о покрытии выполните:

poetry run pytest --cov=code_gen_bot

## Список команд

### Общие команды

*   `/code` — Показать текущий сгенерированный код.

### Команды для администраторов

*   `/start` — Очистить историю кода для текущего чата и запустить первый опрос.
*   `/next` — Завершить текущий опрос, сохранить победивший вариант и запустить следующий.
*   `/code_completed` — "Финализировать" код и получить его в сообщении и в виде `code.py` файла.
*   `/health` — Показать статус бота (uptime, наличие активного опроса).
*   `/logs` — Отправить файл с логами `bot_logs.txt`.
